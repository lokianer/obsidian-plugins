Plugin 01 · Documentation

dnd5e-byLokianer, explained

A game master’s toolkit for D&D 5e in Obsidian. It reads the notes you already keep — factions, characters, sessions, encounters — shows what is in them at a glance and lets you change them in place. This page walks through every module, the conventions it reads and how it works underneath.

  • 7 modules
  • Plain Markdown
  • No network
  • Desktop & mobile
  • English & German

Overview

The plugin is one Obsidian plugin with seven modules. They share one idea: your notes are the truth. Everything the plugin shows — a graph, a stat block, the state of a fight — is built from Markdown files and their frontmatter, and every change it makes is a small edit to one of those files. Switch the plugin off and the notes still read sensibly in any editor.

Module What it does Where you find it
Factions Factions as folders, relations from −5 to +5, a card replacing Properties, a world graph and matrix, tensions, a session history Faction and character notes; Open faction world
NPC builder 5e stat blocks in notes, editable in place; the New NPC dialog with races, archetypes and dice tables dnd5e-statblock blocks; New NPC
Spellbook The SRD’s 319 spells in English and German, own spells, a spell builder Open spellbook, New spell
Deck of Many Things The SRD deck drawn by its rules, own decks, a deck builder Open Deck of Many Things, New deck
Monster Manual 334 SRD monsters as stat blocks, German texts, own monsters, file import Open Monster Manual, New monster
Battle tracker Initiative, hit points, conditions, the fight stored in the encounter note, an encounter builder with the SRD 5.2.1 XP budget Open battle tracker, New encounter
Dice A dice stage like Baldur’s Gate 3, dice: in notes, rollable tables, rolls from stat blocks and the party Open dice; buttons in notes and stat blocks
Status: 0.1.0 All seven modules are released in 0.1.0, each checked inside Obsidian before it counted. The plugin is not in Obsidian’s community directory yet; install it from the release ZIP.

Getting started

Install

  1. Download dnd5e-bylokianer-0.1.0.zip from the release on GitHub.
  2. Unpack it into your vault’s .obsidian/plugins/ folder. It holds dnd5e-bylokianer/ with main.js, manifest.json and styles.css.
  3. Enable dnd5e-byLokianer under Settings → Community plugins, then add a campaign note.

To build from the repository instead (Node 24 and pnpm):

git clone https://github.com/lokianer/obsidian-plugins
cd obsidian-plugins
pnpm install
pnpm --filter dnd5e-bylokianer build
pnpm --filter dnd5e-bylokianer install-example
# open examples/vault in Obsidian, enable dnd5e-byLokianer

install-example copies main.js, manifest.json and styles.css into the example vault’s .obsidian/plugins/.

Try it on Silverstadt first The example vault holds a whole campaign — five factions with secret stances, a party of four, stat blocks, own spells, monsters and decks, encounters, rollable tables and session notes. Its Home.md maps every feature to the notes that show it.

The campaign note

The plugin does nothing until it finds a campaign note: any note whose frontmatter says type: campaign. That note switches the plugin on for its own folder and everything below it; notes outside stay untouched. A campaign note at the vault root covers the whole vault. 

# Silverstadt/Campaign.md
type: campaign
title: Silverstadt
system: D&D 5e (2014 rules)

One campaign per vault for now. With several campaign notes the one with the alphabetically smallest path wins, the others are listed as warnings (“another campaign note is in use”).

A campaign folder

Only factions.md files and the type: of a note carry meaning; folder names are yours. The folders below are the defaults the builders write into (each one can be changed in the settings): 

Silverstadt/
├── Campaign.md              # type: campaign
├── Factions/
│   ├── The Gutter Court/
│   │   ├── factions.md      # the faction
│   │   ├── Mira Voss.md     # type: npc → a member
│   │   └── The Bench/
│   │       └── factions.md  # a sub-faction
│   └── …
├── Party/                   # type: character → the Party
├── NPCs/                    # type: npc outside factions → Unaffiliated
├── Sessions/                # type: session, session: 14
├── Encounters/              # type: encounter
├── Monsters/  Spells/  Decks/  Tables/
Templates/
├── Session.md  NPC.md       # templates for new notes
├── Archetypes/  Races/  Tables/

Core concepts

Note types

The plugin recognises a note by its type: key (case does not matter). Every key and value it reads is English, also in a German vault; German is only a translation of the interface.

type: Meaning Used by
campaign Switches the plugin on for its folder everything
faction A faction (the folder’s factions.md, or a note named like its folder) Factions
npc A non-player character; member of the faction whose folder holds it Factions, NPC builder
character A player character; outside a faction folder it belongs to the Party Factions, Battle, Dice, Deck
session A session note with a whole session: number and a date the session log
encounter A prepared fight Battle tracker
spell · monster · deck Your own spells, monsters and decks Spellbook, Monster Manual, Deck
table A note of rollable tables, listed in the Dice tab Dice
archetype · race Starting points for New NPC NPC builder

Party and characters

Every type: character note in the campaign that is not inside a faction folder belongs to the Party. The Party appears as a frame in the faction world, joins encounters (unless party: false), is suggested as the drawer of the Deck of Many Things and gets its own section in the Dice tab. Characters give the plugin what it needs in their frontmatter: 

type: character
level: 6            # encounter builder budget
ac: 15
hp: 71
initiative: 2       # battle tracker
saves: { str: 7, con: 6 }
skills: { athletics: 7, perception: 2 }   # dice buttons
relations:
  The Archivists: 2

type: npc notes outside every faction folder are grouped as Unaffiliated.

Tonight’s session

Several modules write into the session you are playing. Tonight’s session is the type: session note with the highest session: number. Changes are offered — or written, depending on the settings — as lines under its ## Log heading. If that note’s date: lies before today, the plugin asks once a day whether to start the next session from your session template (default Templates/Session.md, where {{session}} and {{date}} are filled in). See The session log.

How edits are written

Every change the plugin makes is a line edit: it rewrites only the characters it changes and leaves comments, order, quoting and the rest of the note alone. Two rules keep your writing safe:

  • It checks first. Each edit carries the value you saw. If the note says something else now — you edited it elsewhere, sync changed it — nothing is written and a notice says so.
  • It refuses what it cannot edit safely. YAML written in flow style ({ … }), with anchors or tabs is shown but not edited; the notice offers Edit in source, which jumps to the line.

Languages

The interface follows Obsidian’s language: German Obsidian, German plugin; everything else is English. The setting Language of the dice texts can pin the content — dice tables, spell and monster texts, the Deck’s effects — to English or German independently. German texts use metres (5 ft. = 1.5 m) and German dice (2W6). Spellbook, Monster Manual and the deck have an EN / DE switch on each card.

Module 1

Factions

Folders and members

  • A faction is a folder holding a factions.md (or a note named like the folder with type: faction; factions.md wins if both exist).
  • Its members are the npc and character notes in that folder and in its plain subfolders.
  • A faction folder inside another faction folder is a sub-faction. Members belong to the nearest faction above them.
  • The faction’s name is its folder name, unless factions.md sets name:. 
# Factions/The Gutter Court/factions.md
type: faction
power: 3                 # 1–5, the size of its circle
relations:               # the public face
  Order of the Lantern: -4
  The Archivists:
    value: 1
    why: "[[Mira Voss]]"   # an optional reason
secret_relations:        # the true stance, GM only
  The Archivists: -2

Relations

A relation is one-directional: “The Gutter Court towards the Archivists”. Its target is the name of a faction or a character note. Its value is a whole number on an eleven-step scale; each step has a name (renameable in the settings):

−5war −4feud −3hostile −2distrust −1wary 0neutral +1cordial +2friendly +3allied +4close +5sworn
  • Public and true. relations is what the world sees, secret_relations the true stance. A secret value replaces the public one in True mode and never shows in Public mode.
  • Inheritance. A member or sub-faction without its own value towards a target takes its faction’s value. Views draw inherited values dashed; changing one gives the member its own.
  • Short or long form. Target: -4, or value: with a why: beneath it — the reason may hold links.

The faction card

Faction and character notes of the campaign open with a faction card where Obsidian’s Properties block would be, in Reading view and Live Preview. It shows kind and place, name and power, every relation as a coloured row with value, step name and reason, the secret relations (folded) and the note’s other fields. A character’s card also shows AC, HP, CR, speed and the six ability modifiers from the note’s first stat block.

Everything on it is editable: drag a slider, click a name, a reason or a power pip. Lists such as tags are shown but edited in source. Source mode still shows the raw YAML; the setting Show Obsidian’s properties on faction notes brings Properties back beside the card. Edit faction data focuses the card of the active note.

Faction world

Open faction world (command or ribbon) opens a tab with every faction of the campaign, in two modes:

  • Graph. Factions as circles sized by power, each in its own colour (shared by its sub-factions and members); the Party and Unaffiliated as frames; unknown targets as dashed ghosts. Arrows run from red (−5) to green (+5); friends cluster, enemies drift apart. Hover a faction to light up its stances, drag one to pin it, drag the background to pan, scroll or pinch to zoom; Ctrl/Cmd-click opens its note.
  • Matrix. Who (rows) towards whom (columns), each cell with number and step name; inherited values dashed.

The Public / True toggle starts at Public every time the view opens. True adds the secret stances and marks where they differ from the public face.

Click an arrow or a cell to edit that value in a popover: slider, reason, where an inherited value comes from, Reset to inherited and Open card. The write always lands in the subject’s own note.

Faction view

Click a faction (or the Party / Unaffiliated frame) to drill into it: the faction as a frame with its members as pills, the factions it relates to around it. Members whose own values differ from their faction’s line get a yellow ring. Click a member to see all its stances, a sub-faction to go one level deeper; the breadcrumb leads back. Positions you drag are kept per faction; the re-layout button resets them.

Tensions

The lightning button in the world’s header (or Show faction tensions) opens a sidebar that lists where the story is pulling. It follows the Public / True toggle; the thresholds are settings.

Finding Reported when Default
One-sided pair A → B and B → A differ by at least the threshold 4
Out of line A member’s own value differs from its faction’s by at least the threshold 3
Public vs. true A secret stance differs from the public face (True mode only) 3
Split allies Two allies stand on opposite sides of a third faction 3

Warnings

A broken value never blanks a view. The plugin reads what it can and collects the rest as warnings: a value outside −5 … +5 or not a number, a power outside 1 … 5, a target no faction or character is called, a relation to itself, two notes with the same name, a factions.md without type: faction, frontmatter that is not valid YAML. Show faction warnings lists them grouped by note; Fix opens the note’s card on the broken entry.

History and loot

After every change of a relation value a notice offers Log, naming tonight’s session. A click writes a line under its ## Log; secret changes go into a [!gm] callout: 

## Log
- 20:31 Order of the Lantern → The Gutter Court: −2 → −3
> [!gm]
> - 21:52 The Bench → Order of the Lantern: −4 → +4

The views read those lines back: each relation’s tooltip shows its last changes. Start next session makes the next session note from the template and carries the last session’s ## Loot over — table rows and list items, each marked with where it was found ((from [[Session 14 – Bell Square]])), so only the newest session needs watching.

Module 2

Stat blocks and NPCs

The stat block

A fenced dnd5e-statblock block holds a 5e stat block in YAML, with the keys Fantasy Statblocks uses — so blocks move between the two plugins: 

```dnd5e-statblock
name: Mira Voss
size: Medium
type: humanoid
ac: 16
ac_class: studded leather
hp: 84
hit_dice: 13d8 + 26
speed: 30 ft.
stats: [11, 18, 14, 16, 13, 15]
saves:
  - dexterity: 7
skillsaves:
  - deception: 8
cr: 5
traits:
  - name: Cunning Action
    desc: …
actions:
  - name: Rapier
    desc: "Melee Weapon Attack: +7 to hit, …"
```

It renders folded behind one line — Stat block · Mira Voss · AC 16 · HP 84 · CR 5 — and opens with a click into the full block: modifiers, XP and proficiency bonus worked out. Convert stat block switches a note’s blocks between dnd5e-statblock and Fantasy Statblocks’ statblock. The 21 NPC stat blocks of the SRD 5.1 ship with the plugin.

Editing a block

An opened block is editable where it stands: click the name, AC, HP, speed, senses, languages, CR or an ability score, type, Enter writes, Esc cancels. Traits, actions, bonus actions and reactions show a pencil and × (with Undo) on hover and + Add under each section. Each change is one line edit inside the block — and refused if the note changed in the meantime.

New NPC

New NPC (command, or the button on a faction’s card) opens a dialog: the form on the left, a live preview card on the right.

  1. Pick from tiles. Race (the nine SRD races and your own), archetype (the 21 SRD NPCs and your own, with AC · HP · CR) and class (the twelve SRD classes). A race typed without a tile still works as free text.
  2. Roll. Each descriptive line — appearance, build, manner, voice, occupation, wants, ideal, bond, flaw, quirk, secret, hook — has a die. Roll everything rolls the race and every field that is not locked.
  3. Lock what you like. Every rolled field has a lock; typing into a field locks it. Faction, archetype and alignment are never rolled.
  4. Create. The note is made from your NPC template (default Templates/NPC.md, {{title}} becomes the name) in the faction’s folder — the Party’s for the Party, the campaign’s NPCs folder for the unaffiliated — with the archetype’s stat block named after the NPC and the race’s traits written in (size, speed, darkvision, languages, resistances; never ability scores).

Add stat block gives the open note a stat block from an archetype under a new ## Stats heading.

Archetypes, races and dice tables

  • Archetypes — notes with type: archetype and a stat block in Templates/Archetypes/. New archetype writes one from an existing archetype or from nothing.
  • Races — type: race notes in Templates/Races/. New race writes one from a base race.
  • Dice tables — every built-in table has at least fifty entries in English and German. A note such as Templates/Tables/NPC quirks.md, one entry per list item, replaces that table.

Module 3

Spellbook

Open spellbook (command, or the book in the ribbon) opens the 319 spells of the SRD 5.1. Search by English or German name — case and accents do not matter — and narrow by level and school chips (each with its count), class, casting time, damage type, saving throw, concentration and ritual. ↑ ↓ move through the list, Enter opens the card. The card shows the spell in both languages with its level line, meta, badges, description and “At Higher Levels”.

In an opened stat block, spell names in a Spellcasting trait are links: a click opens the spellbook on that spell.

Own spells

A note anywhere in the vault with type: spell joins the list, marked “own”: 

type: spell
level: 2              # 0 or "cantrip" for a cantrip
school: abjuration   # English or German
casting_time: 1 action
range: 30 feet
components: V, S, M
material: a lantern's wick
duration: Up to 1 hour
concentration: true
classes: [Cleric, Wizard]
damage: radiant       # optional; also save:, attack:

The body is the description; a ## At Higher Levels heading adds that part. A note without a valid level or school stays out. New spell opens the spell builder: start from any SRD spell (its text arrives in your language), fill the fields by hand, or load a JSON file (these keys, or the 5e-bits and Open5e shapes). It writes into the spell folder (default Spells).

Module 4

Deck of Many Things

Open Deck of Many Things puts the SRD’s deck on the table — 22 cards, or 13 with the setting. Name who draws (the party is suggested), declare the number of cards and turn them one by one. The rules run themselves: the Fool and the Jester leave the deck, every other card returns; the Fool’s redraw counts as the same draw; the Jester offers 10,000 XP or two more draws, the Idiot one more; The Void and Donjon end the drawing.

The deck lives in a note, made on the first draw:

type: deck
deck: standard-22
---
- [ ] Vizier
- [ ] Sun
- [x] Fool          # ticked = out of the deck

## Draws
- 2026-10-25 · [[Mira]] · Fool

Tick or untick a card by hand and the tab follows. The reset button (↺) clears the history, or also puts every card back.

Own decks

Any type: deck note in the campaign shows in the deck list. Its first task list is the deck, one card per item, Name — effect: 

type: deck
returns: true                  # drawn cards go back in
leaves: ['The Cracked Bell']   # …except these
ends: ['Midnight']             # these end the drawing
---
- [ ] The Lantern — Someone you trust keeps a light burning for you.
- [ ] Midnight — No more fortunes tonight.

New deck opens the deck builder: type cards one by one, start from the standard deck, paste text (Name — effect, Name: effect, **Name.** effect, list items or table rows) or load JSON. It writes into the deck folder (default Decks).

Module 5

Monster Manual

Open Monster Manual (the skull in the ribbon) lists the 334 monsters of the SRD 5.1, built like the spellbook. Filter by challenge rating band (0–½, 1–4, 5–10, 11–16, 17+), type, size, movement (flies, swims, burrows, climbs), Legendary and Spellcaster. The card is the full stat block — the same view as in your notes — with dice buttons and spell links. In German, names, types, metres and every trait and action are German.

  • Insert into note puts the block below the cursor of the last note you were in.
  • Make a note writes a type: monster note into the monster folder (default Monsters).
  • Add to combat / Add to encounter hand it to the battle tracker.

Own monsters and import

A type: monster note with a dnd5e-statblock block anywhere in the vault joins the list as “own”. New monster opens the monster builder: start from any SRD monster or from nothing; size, type, alignment and CR are dropdowns, saves and skills one line each (DEX +6, CON +13), traits and actions rows. Import from a file reads Fantasy Statblocks YAML/JSON or Markdown, the 5e-bits and Open5e JSON shapes and 5etools bestiary files; several monsters show as tiles, with Create all. Monsters outside the SRD are not shipped — bring them from your own books this way.

Module 6

Battle tracker

The encounter note

A fight starts from any type: encounter note in the campaign:

type: encounter
party: true                 # the party joins (default)
combatants:
  - "[[Sable]]"               # a note: ac/hp/initiative, else its stat block
  - monster: Owlbear          # Monster Manual, English or German name
    count: 2
  - name: Court thug          # written right here
    count: 4
    ac: 11
    hp: 32
    initiative: 0
    side: enemy               # party, ally or enemy

Running a fight

  1. Start. Monsters and NPCs roll d20 + initiative (a group with a count rolls once and is numbered “Court thug 1 … 4”); player characters’ numbers are typed in or rolled. Ties go to the higher Dexterity; arrows nudge a row.
  2. Begin round 1, then Next turn (and back). Defeated monsters are skipped.
  3. Pick a row for its card: one number with Damage, Heal and Temp HP (temporary hit points absorb damage first and don’t stack), death saves when a character is down, the SRD conditions as chips with an optional duration that counts down at the end of the combatant’s turn, concentration — damage shows the Constitution save’s DC — and the stat block with dice buttons.
  4. Change the line-up while it runs: type a monster, a note or a name with HP and AC and press Add; Remove from fight takes someone out.
  5. End combat closes the fight.

Every change is written to the note’s ## Combat section, a plain table that reads without the plugin and is read back when the tab opens — the fight survives a restart: 

## Combat

Round 3 · Turn: Court thug 2

| Init | Combatant    |       HP |  AC | Conditions               |
| ---: | ------------ | -------: | --: | ------------------------ |
|   21 | [[Dagny]]    | 54/71 +5 |  15 | prone (1), concentration |
|   17 | Court thug 2 |    12/32 |  11 |                          |
|    9 | Owlbear 1    |     0/59 |  13 | defeated                 |

The fight’s moments — begin, defeated, down, dead, end — go to tonight’s session. The ⋮ menu offers Reset the fight and Remove battle lines from tonight’s session.

Encounter builder

New encounter builds an encounter note: a name and place, the party as chips with their levels (from each character’s level, or a number of characters and a level), the difficulty — Low, Moderate or High, each with its XP budget from the SRD 5.2.1 table, summed over the characters — and the Monster Manual as tiles. The preview fills the budget as you add monsters.

Milestone or XP With Experience points off (the default) the builder shows how much of the budget is used but no XP, and the log’s end line carries none. Switched on, budgets and every monster’s XP show, and the end line sums the defeated enemies’ XP.

Module 7

Dice

Open dice opens the Dice tab: type a formula and press Roll, or pick a die. Normal / Advantage / Disadvantage applies to a single d20; a DC gives the verdict. Each roll plays on the dice stage: the DC on top, every die in its own shape tumbling and landing, the bonuses flying in, the total counting up, then Success or Failure — a natural 20 with golden rays. A click or Space skips to the result. The rolls of this Obsidian session are listed with Roll again and Log.

Formulas

Written Meaning
d20, W20 one twenty-sided die (German W works everywhere)
2d6+3, 1d8+2d6-1 sums; *, / and brackets too
d%, d100 percentile (two d10, tens and ones)
4d6kh3, 2d20kl1, 4d6dl1 keep highest / keep lowest / drop lowest
d20+5 adv, d20 dis advantage / disadvantage

Dice in notes

Inline code like `dice: 2d6+3` — Dice Roller’s syntax, so notes work with both plugins — becomes a button in Reading view and Live Preview. A click plays the stage in a small window and shows the total beside the button; nothing is written into the note. Formulas the plugin does not read (exploding dice, rerolls) stay as they are.

Rollable tables

A heading that ends in a die in brackets makes the first list or table under it rollable. A list is numbered in order; a table’s first column holds numbers or ranges. 

## Weather on the estuary (1d8)

| d8  | Weather                                 |
| --- | --------------------------------------- |
| 1   | Fog, visibility 30 feet                 |
| 2–4 | Grey and dry                            |
| 5-6 | Rain, and the [[Lantern Bridge]] slick  |

Every type: table note shows its tables in the Dice tab. `dice: [[Street Rumours#Night on Lantern Quay (d20)]]` rolls one table from a note, `dice: [[Street Rumours]]` the note’s first. The row shows with its links working; a total that lands on no row is recorded as “no row”, never re-rolled.

Stat blocks and the party

In every stat block — notes, Monster Manual, Battle tab — attack bonuses (+7 to hit), damage (10 (1d10 + 5)), saves, skills and the ability modifiers are buttons:

Gesture Roll
Click Normal
Shift-click Advantage — on a damage button: a critical hit (dice twice, numbers once)
Alt-click Disadvantage
Right-click / long press A menu with all choices

Saving throw DCs stay text — the target rolls those. Characters’ saves and skills from their frontmatter appear as buttons in the Dice tab’s Party section and on their Battle card, rolled with the tab’s Advantage and DC.

The session log

The session note is the spine of the plugin: factions, battle tracker and dice all append to ## Log of tonight’s session, each line with its time. 

## Log
- 20:10 Rolled d20+7 → 19 (12, +7) against DC 15: success
- 20:31 Order of the Lantern → The Gutter Court: −2 → −3
- 21:40 Combat begins: [[Ambush under the second arch]]
- 21:52 Round 3: Owlbear 1 defeated
- 21:58 Combat ends after 5 rounds — 1,400 XP
> [!gm]
> - 22:05 The Bench → Order of the Lantern: −4 → +4
Source When it writes
Relations A notice with Log after every value change; secret ones go in a GM callout
Battle Setting Battle log: offer each line (default), write automatically, or off
Dice Setting Dice log: offer each roll (default), write automatically, or off

Remove battle lines and Remove dice lines from tonight’s session ask first and touch only the lines those modules wrote; relation changes, your own lines and [!gm] callouts stay.

How it works inside

For the curious — and for anyone who wants to read or change the code in plugins/dnd5e-bylokianer/src/.

Two layers

Pure modules (factions/, npc/, spells/, monsters/, deck/, battle/, dice/, yaml/, campaign/) hold all rules and parsing: plain TypeScript without the Obsidian API, tested in Node with Vitest.

Adapters in obsidian/ connect them to Obsidian: views, modals, code-block processors, the settings tab. main.ts only loads the settings and calls one register… function per module.

  1. Read. On load and after every change in Obsidian’s metadata cache (debounced, never per keystroke) the plugin collects the frontmatter of the campaign’s notes, finds the campaign, factions, members and sessions and builds one world — with the warnings for whatever it could not read.
  2. Show. Cards, graph, matrix and panels render from that world with the DOM API (never innerHTML with note content) and Obsidian’s CSS variables, so every theme works.
  3. Write. An edit is computed as a line operation on the note’s text (yaml/edit.ts) carrying the value last seen, and applied through app.vault.process. A mismatch refuses the edit; frontmatter is never re-serialised.
  4. Rebuild. The write changes the file, the metadata cache fires, the world is rebuilt and every open view follows.

Big data — the 319 spells, 334 monsters, 21 NPCs, nine races and the German texts — ships inside main.js, extracted from the SRD by scripts in scripts/. The session logic (tonight’s session, the log, loot carry-over) lives in the shared package packages/session. There are no network calls, no telemetry and no Node APIs, which is why the plugin runs on mobile too.

Troubleshooting

Nothing happens — no card, no world.

Is there a type: campaign note, and is the note you look at in its folder or below it? Is the plugin enabled?

“The note changed” — my edit was not written.

The note says something else than the view showed: edited elsewhere, synced, or just created outside Obsidian and not indexed yet. Wait a moment and try again; the view refreshes on its own.

“Cannot edit safely”.

The line uses flow style { … }, an anchor or tabs. Click Edit in source and change it by hand, or rewrite it in block style once.

A faction or member is missing.

Run Show faction warnings. Common causes: the folder has no factions.md, the character note has no type: npc / character, or two notes share a name.

Log lines go to the wrong session.

Tonight’s session is the highest session: number. Check that the new note has a whole number there — or use Start next session.

A dice: button does not appear.

It has to be inline code (in backticks) and a formula the plugin reads; exploding dice and rerolls are left to Dice Roller.
